三种用法

同一支团队，三种用法。

桌面应用、randcomp 命令和 MCP 驱动的是同一家本地公司：同样的项目、同样的文件，绝不会多出一份副本。哪种顺手就用哪种。

randcomp 命令行

在终端或脚本里驱动同一家公司——也可以从另一台机器 SSH 进来用。每条命令都输出 JSON。

randcomp project create "做一个阅读清单网站"
randcomp project list
randcomp project ask PROJECT_ID "加一个搜索框"

从应用菜单安装：RandComp Studio → Install the randcomp command in PATH。全部命令 →

MCP：在你自己的 AI 助手里

问 Claude Code、Claude Desktop、Codex 或其他 MCP 客户端“团队进展如何”，也可以直接把活交给它——不用离开你正在用的对话。

纯本地

一切都在你自己的电脑上发生。

RandComp Studio 是一个桌面应用，不是云服务。不用注册账号，你和智能体之间也没有任何 RandComp 服务器：应用、项目、每个智能体的终端和它写下的每个文件，都留在你的电脑上。它调用的是你已经装好的 AI 命令行工具——Claude Code、Codex、Kimi Code 或 Ollama——和你自己在终端里用它们没什么两样。

会离开你电脑的，全都列在这里
  • 提示词和代码 → 你选的 AI 工具。Claude Code 连接 Anthropic，Codex 连接 OpenAI，Kimi 连接月之暗面——用的都是你自己的账号，和你平时单独使用它们一样。用本机模型（Ollama）时，什么都不会离开。
  • 匿名使用计数 → RandComp。只有四类事件：打开应用（每天最多记一次）、创建项目、连接 MCP 客户端、发送消息。每条只有事件名、UTC 时间和一个随机安装 ID——不含内容、项目名或文件路径。默认开启；在“设置 → 使用统计”里可以关闭，关闭后还没发出的记录会一并删除。

除此之外，别无其他。RandComp 账号：没有 · RandComp 保存的工作副本：没有 · 发给 RandComp 的提示词和文件：没有。应用自己的服务只监听 127.0.0.1。

拔掉网线试试。用本机模型（Ollama）的角色断网也照常工作；用 Claude Code、Codex 或 Kimi 的角色在恢复联网之前得不到回应，因为它们的服务商在网上。RandComp 本身不需要联网。

需要说明的局限：“本地”指的是 RandComp 自己不加任何云端，并不能让 Claude Code、Codex 或 Kimi 离线工作。另外，较小的本机模型只适合小而明确的工作。

每份工作用对的 AI

不是一个 AI 给自己的作业打分。

检查员从未看过建造者的思路，甚至可以是完全不同的 AI。随意搭配——规划用强的模型，日常活用便宜的，敏感文件用私有的。

每个角色单独选

规划用 Claude Code，实现用 Codex，快速检查用 Kimi，草稿交给你本机上的模型。随时可换，项目进行中也行。

独立检查

检查员依据成果本身工作，而不是听建造者的说法，因此盲区不会被共享。这是多一双眼睛，而不是保证一切正确。

一个够用，就只用一个

智能体越多，消耗的 Token 越多。小任务保持一个会话；团队留给值得的工作。

它是怎么来的

关于 RandComp

起因是我在旅行的时候。我想让 agent 帮我在家里的 Mac mini 上干活——但一个 AI 会话跑长了很容易失控：跑偏、丢目标、没人把关。所以我不再让一个 agent 包打天下，而是开了一家"公司"：协调员负责规划，每个角色各司其职，我在任何地方都能接管其中任何一个。后来我一直自己用它——陆续用它做了好几个小应用，它渐渐成了我默认的工作方式。觉得真正好用了，才决定把它分享出来。至于名字——实在想不出来，就叫 Random Company 吧，RandComp 只是偷懒的简称。
