其一 · 纯本地

一切都发生在你的 Mac 里。

RandComp Studio 是一个桌面应用，不是云服务。不用注册账号，你和智能体之间也没有任何 RandComp 服务器：应用、项目、每个智能体的终端和它写下的每个文件，都留在你的 Mac 上。它调用的是你已经装好的 AI 命令行工具——Claude Code、Codex、Kimi Code 或 Ollama——和你自己在终端里用它们没什么两样。

会离开你 Mac 的，全都列在这里
  • 提示词和代码 → 你选的 AI 工具。Claude Code 连接 Anthropic，Codex 连接 OpenAI，Kimi 连接月之暗面——用的都是你自己的账号，和你平时单独使用它们一样。用本机模型（Ollama）时，什么都不会离开。
  • 匿名使用计数 → RandComp。只有四类事件：打开应用（每天最多记一次）、创建项目、连接 MCP 客户端、发送消息。每条只有事件名、UTC 时间和一个随机安装 ID——不含内容、项目名或文件路径。默认开启；在“设置 → 使用统计”里可以关闭，关闭后还没发出的记录会一并删除。

除此之外，别无其他。RandComp 账号：没有 · RandComp 保存的工作副本：没有 · 发给 RandComp 的提示词和文件：没有。应用自己的服务只监听 127.0.0.1。

亲自试试。在上面的演示里断开网络——使用云端 AI 工具的角色会暂停（它们的服务商需要联网），而使用本机模型的角色继续工作。RandComp 本身从不需要联网。

已联网

需要说明的局限：“本地”指的是 RandComp 自己不加任何云端，并不能让 Claude Code、Codex 或 Kimi 离线工作。本机模型断网也能继续，但较小的本机模型只适合小而明确的工作。

其二 · 每份工作用对的 AI

不是一个 AI 给自己的作业打分。

检查员从未看过建造者的思路，甚至可以是完全不同的 AI。随意搭配——规划用强的模型，日常活用便宜的，敏感文件用私有的。

每个角色单独选

规划用 Claude Code，实现用 Codex，快速检查用 Kimi，草稿交给你本机上的模型。随时可换，项目进行中也行。

独立检查

检查员依据成果本身工作，而不是听建造者的说法，因此盲区不会被共享。这是多一双眼睛，而不是保证一切正确。

一个够用，就只用一个

智能体越多，消耗的 Token 越多。小任务保持一个会话；团队留给值得的工作。

给开发者

从终端或你的 AI 助手连到你的团队。

桌面应用是最轻松的入口。同一支本地团队也可以用脚本控制：从任何地方 SSH 回你的 Mac，使用 randcomp 命令；或者让任何支持 MCP 的 AI 工具连到同一个本地进程，问它有什么需要你处理。项目只有一个、文件只有一套——绝不会多出一份副本。

# 通过 SSH，从另一台机器
randcomp project list
randcomp project ask PROJECT_ID "增加一个礼品卡页面"

# MCP 客户端（Claude Code、Kimi 等）运行：
randcomp mcp

从应用菜单安装附带的 randcomp 命令。命令行和 MCP 服务只与你 Mac 上的 RandComp 进程通信，中间没有额外的云端。

它是怎么来的

关于 RandComp

起因是我在旅行的时候。我想让 agent 帮我在家里的 Mac mini 上干活——但一个 AI 会话跑长了很容易失控：跑偏、丢目标、没人把关。所以我不再让一个 agent 包打天下，而是开了一家"公司"：协调员负责规划，每个角色各司其职，我在任何地方都能接管其中任何一个。后来我一直自己用它——陆续用它做了好几个小应用，它渐渐成了我默认的工作方式。觉得真正好用了，才决定把它分享出来。至于名字——实在想不出来，就叫 Random Company 吧，RandComp 只是偷懒的简称。
