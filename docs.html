Documentation

Run your agent company.

Mission Control does not replace your coding agent or skill ecosystem. It coordinates the tools and role definitions you already prefer, while keeping every task, agent, session, and result under your control.

Start here: Quick start · First task · UI · CLI

Get started

Quick start

Mission Control currently runs on macOS. It needs Python 3.11 or newer, tmux for agent sessions, and either Claude Code or Codex CLI installed and signed in.

Private preview

The product download is not public yet. Open an issue if you want to try the preview or share feedback. Installation instructions are included with approved preview builds.

Get preview access

Open an issue to request the current private macOS preview.

Install two small commands

The installer writes mctl and mission-control into ~/.local/bin. They run the same program.

Open Mission Control

The first run asks where your company should live and which installed coding-agent CLI should run its agents.

mctl
What the installer changes

It creates two shell scripts in ~/.local/bin. It installs no Python packages, creates no virtual environment, and starts no background service.

First-run questions

The company folder holds roles, tasks, decisions, status, messages, and results as ordinary files. It is not necessarily the codebase where agents work. You choose project folders separately for each task.

If both Claude Code and Codex CLI are installed, Mission Control asks which one should run coordinators. It checks whether the selected runner appears signed in, but never reads or stores the credential value and never signs in for you.

Five minutes

Run your first task

From the UI

  1. Run mctl to open the company window.
  2. Describe the outcome in the main input.
  3. Choose where the work should happen. This is the project folder agents may edit.
  4. Review the roles. Let the coordinator choose, or narrow the available set yourself.
  5. Leave unattended spending off unless you intentionally want sessions to run without approval prompts.
  6. Send the task. Mission Control creates the task, starts its coordinator, and hires the matching specialist roles.

From the CLI

mctl task create "Review the checkout flow and fix the highest-risk defect" --in ~/code/storefront
mctl task list
mctl agent list TASK_ID
mctl task results TASK_ID

Copy TASK_ID from mctl task list. Results lists the files; it does not print them. Use mctl task show RESULT_FILE_PATH to print one file.

Core concepts

The mental model

ConceptWhat it means
CompanyThe durable folder containing your roles, tasks, decisions, messages, status, and produced artifacts.
Project folderThe codebase or working folder an agent operates in. It is selected per task and can be outside the company.
RoleA reusable definition such as Developer, QA, or Market Analyst. Roles live in the library; they do not run by themselves.
AgentOne hired instance of a role on exactly one task. Two tasks using Developer get two different Developer agents.
SessionOne running terminal for an agent. Sessions cost money; agents and their history remain when sessions stop.
TaskOne piece of work, its assigned agents, live state, outcome, and files. Every dispatched task has its own coordinator.
RunnerThe installed coding-agent program—currently Claude Code or Codex CLI—that executes an agent.
Roles are the company; agents are the people on the work.

The role library has no live graph. Relationships and arrows only make sense inside one task, between the agent instances hired onto it.

Graphical interface

Use the UI

Run mctl for the app window. Run mctl ui for the same company in a browser tab served only to 127.0.0.1.

Tasks

Create work, see its project folder and current state, open the task map, inspect every agent, and read what came out.

Roles

Browse the reusable role library, read role definitions, inspect track records, import a definition, or start a task with one role.

Agent detail

Read reported progress and live scrollback, send a message, open the terminal, or stop the session without deleting the agent.

History

Review recorded company activity and artifacts without pretending that old work is still running.

Read task state

A task’s state is derived from its agents rather than stored as a guess. Needs you means an agent recorded a blocker or request. Working means current work is active. Done means the task was finished. A quiet or unknown agent is explained with its cause instead of being silently called blocked.

Talk to an agent

Open an agent from its task, read its current terminal output, and send a line. “Open in a terminal” joins the actual tmux session; detach with Ctrl-B, then D, and the agent keeps working.

Command line

Use the CLI

mctl and mission-control are identical. Commands use a noun-first grammar: mctl task list, mctl agent logs, mctl role library.

Capitalized words come from your own screen.

Get TASK_ID from mctl task list, AGENT_ID from mctl agent list, and RESULT_FILE_PATH from mctl task results.

Inspect the whole company

mctl status
mctl task list
mctl agent list
mctl inbox

status is the concise company summary. inbox answers what needs you, including actionable review state, stopped sessions, and your reminders.

Use another company

mctl task list --company ~/Companies/acme
mctl app --company ~/Companies/new-company

--company PATH works across the command surface. Naming a path that does not exist creates a company there. It does not change the project folder agents work in.

Reference

Complete CLI reference

This reference follows the public parsers in the current source. Brackets mean optional input. Every command also accepts -h or --help; mctl help prints the top-level map.

Values and shared behavior

ValueWhere it comes from
TASK_IDThe short slug beside a task in mctl task list, or enough of its long name to match exactly one task.
AGENT_IDThe ID in brackets after a role in mctl agent list. A role name also works when only one agent has that role.
RESULT_FILE_PATHThe complete path printed under “what it produced” by mctl task results TASK_ID.
TODO_IDThe short ID printed beside your reminder by mctl inbox.
ADDRESSA hired agent ID or an unambiguous role name.

--company PATH is accepted by task, agent, role, status, app, and UI commands. It selects the folder holding roles/ and coordination/; it does not select an agent’s project folder. The remembered first-run company is the default. A named path that does not exist is initialized as a company. On role commands the flag may appear before or after the verb.

Tasks

mctl task create TEXT... [OPTIONS]

Open a task, start its coordinator, and let the coordinator hire the roles it needs.

  • --name WORDS sets the display name and the basis of the short task slug. The request text is the default.
  • --in PATH sets the project folder every agent opens. The last project folder used is the default.
  • --only ROLE,ROLE limits which roles the coordinator may consider and remembers that narrowing. --only all clears it.
  • --with-role ROLE hires one role you chose instead of asking the coordinator to choose it.
  • --let-it-work-without-asking requests the runner’s unattended permission mode. This lowers an approval boundary; role library prints what the runner permits.
  • --anyway confirms the new spend when sessions are already running. Without it, Mission Control reports what is running and stops.
mctl task list [--json] [--company PATH]

Print the company org chart: every task, derived state, agent, and ready-to-run command. --json returns the same listing as structured JSON.

mctl task results [TASK_ID] [--json] [--company PATH]

Show what was requested, the coordinator’s outcome, participants, and complete paths of produced files. The task may be omitted when it can be resolved interactively. It lists files rather than printing their contents. --json produces structured output.

mctl task show [RESULT_FILE_PATH] [--company PATH]

Print one produced document whole. Use the exact path from task results; the path may be omitted when it can be resolved interactively.

mctl task finish [TASK_ID] [--yes] [--company PATH]

Close a task and stop every agent session on it. In a terminal it names the sessions and asks first. --yes answers in advance; non-interactive scripts are never prompted. Agents and history remain.

mctl task reopen [TASK_ID] [--company PATH]

Open a finished task again. It deliberately starts no sessions; list the old agents and run agent start only for those you want working.

Agents

mctl agent list [TASK_ID] [--json] [--company PATH]

List agents on one task, or every agent when the task is omitted. --json returns structured output.

mctl agent logs [AGENT_ID] [--company PATH]

Read the agent’s words: full live scrollback while it runs, or its saved conversation after it stops. This is not the reusable role definition.

mctl agent send [AGENT_ID] [TEXT...] [--company PATH]

Write a line to an agent. It enters the live session, or waits in the agent’s inbox when no session is running.

mctl agent attach [AGENT_ID] [--print-the-command] [--company PATH]

Join the tmux session in this terminal; detach with Ctrl-B, then D. --print-the-command prints the join command without running it, for another terminal or script.

mctl agent start [AGENT_ID] [--company PATH]
mctl agent stop [AGENT_ID] [--company PATH]

start gives the durable agent a session, resuming its identity and history. stop ends only that session; the agent stays and can start again.

Role library and hiring

mctl role library [--company PATH]

List reusable role definitions, their selection cues, and what installed runner can execute each. role roles is the older equivalent.

mctl role add ROLE [OPTIONS]

Write down one hired instance of a reusable role. Hiring does not necessarily launch it.

  • --assignment WORDS... records this instance’s one piece of work; it may be added later.
  • --in PATH sets the project folder the agent opens. The company folder is the default. The legacy hidden spelling --project PATH is equivalent.
  • --task SLUG binds the agent to one task’s coordination-directory slug. Omit it only for genuinely cross-task work.
  • --because WORDS records why the task needs this role.
  • --runner NAME chooses the runner; otherwise the installed configured default is used.
mctl role assign ADDRESS --assignment WORDS... [--continue] [--company PATH]

Change an agent’s assignment. A different piece of work is refused because one agent session owns one assignment. --continue explicitly says this is the same work described more clearly.

mctl role outcome --task SLUG [WORDS...] [--company PATH]

Record the task’s concise outcome, produced paths, conclusions, and remaining work. Supplying no outcome words clears an incorrect outcome.

mctl role list [--all] [--company PATH]

List the hired roster and what is running. --all includes retired hires. role roster is equivalent.

mctl role retire ADDRESS [--company PATH]

Stop listing a hire as active. Its recorded history is retained.

mctl role import PATH [OPTIONS]

Translate an existing skill, agent, GPT export, AGENTS.md, or Markdown definition into a Mission Control role package. PATH may be a file, a containing directory, or - for stdin.

  • --as NAME overrides the inferred role name.
  • Without --add, it writes nothing and prints the proposed package for review.
  • --add copies the translation into role-library/<name>/ and generates roles/<NAME>.md. It never edits the source or overwrites an existing role.
  • --anyway permits writing despite non-fatal missing information; it cannot override a missing name, missing mission, or overwrite refusal.

Role sessions and runners

mctl role runners [--company PATH]

List every configured runner, whether it is installed and signed in, and which runner is the default.

mctl role coordinator [--use NAME | --default] [--company PATH]

With no option, show the runner used for new coordinators. --use remembers a new choice. --default forgets that choice and returns to the runner table’s default. Existing coordinator sessions are unchanged.

mctl role runs-on ADDRESS [--use NAME] [--wait SECONDS] [--company PATH]

Show one agent’s runner. --use moves it to another runner. If it is live, Mission Control requests and verifies a handover before replacing anything; --wait sets the handover deadline, using the runtime default when omitted.

mctl role launch ADDRESS [--let-it-work-without-asking] [--company PATH]

Give a hired agent a session. The unattended flag is an explicit safety-boundary reduction and is refused if that runner has no defined unattended mode.

mctl role stop ADDRESS [--company PATH]
mctl role attach ADDRESS [--company PATH]

stop ends the session but keeps the hire. Role-level attach prints the command that joins the session; the noun-first agent attach command joins it directly.

mctl role replace ADDRESS [--wait SECONDS] [--let-it-work-without-asking] [--company PATH]

Ask a live agent for a handover, verify it, retire the old session, and start a fresh continuation. If the handover misses the timeout, the old session is left exactly as it was.

mctl role at-once [HOW_MANY] [--company PATH]

Show or set how many specialist agents on each task may run simultaneously. Extra hires wait their turn. The task coordinator is not counted. The old at-most command was removed and only explains its replacement.

mctl role check ADDRESS [--company PATH]
mctl role history ADDRESS [--company PATH]

check takes everything waiting from an agent’s inbox. history shows every session that hire has had and the succession between sessions.

Role messages

mctl role say ADDRESS TEXT... [--about TASK_ID] [--company PATH]

Send a founder-authored message. --about disambiguates the task when writing to the cross-task coordinator.

mctl role send --to ADDRESS --from NAME [--as-founder] TEXT... [--company PATH]

Send a message from one role to another. --from records the truthful sender; --as-founder explicitly marks the message as founder-authored.

mctl role route [--company PATH]

Deliver everything currently waiting in the role outbox.

mctl role read ADDRESS [--lines N] [--company PATH]

Read the full live scrollback or saved conversation. --lines N limits only live scrollback; completed conversations are always shown whole.

mctl role inbox [ADDRESS] [--company PATH]

Show unread messages for one recipient, or for every recipient when the address is omitted.

Private reminders

mctl todo add TEXT... [--in PATH] [--at EPOCH] [--log FILE]

Add your own reminder without opening a task, hiring anyone, or starting anything. --in associates another folder; --at supplies a Unix timestamp for replay/testing; --log selects another event log.

mctl todo note TEXT... [--on TODO_ID] [--in PATH] [--at EPOCH] [--log FILE]

Append one line to a reminder. Without --on, Mission Control uses the open reminder in the current or --in folder.

mctl todo done TODO_ID [--at EPOCH] [--log FILE]

Finish a private reminder so it leaves the inbox. This is distinct from task finish, which settles a task and its agent sessions.

Company status, attention, and handoff

mctl status [--json] [--company PATH]

Print the selected runner and sign-in state, task and agent counts, then one concise line for each. --json returns structured output.

mctl inbox [--repos PATH] [--log FILE] [--why] [--no-ingest]

Answer what needs you: actionable reviews, stopped sessions, and reminders. --repos accepts a checkout or parent directory and is repeatable; --log selects another event log; --why also prints deliberately suppressed pull requests; --no-ingest judges existing log data without reading sources first.

mctl handoff [--repos PATH] [--log FILE] [--repo NAME] [--out FILE] [--no-ingest]

Render everything still open as Markdown. --repos is repeatable; --repo limits reminders to one repository; --out writes a file instead of stdout; --no-ingest uses the existing log without refreshing GitHub.

App and browser interface

mctl [--repos PATH] [--log FILE] [--why] [--no-ingest]
mctl app [--repos PATH] [--log FILE] [--no-model] [--company PATH]

Bare mctl opens the native company window; app is its older explicit spelling. Supplying report flags to the bare command prints the inbox report. On app, --no-model disables the optional local-model paragraph.

mctl ui [--repos PATH] [--log FILE] [--port PORT] [--no-browser] [--no-model] [--company PATH]

Serve the same company page on this machine only. The default port is any free port; --port fixes it, --no-browser serves without opening a tab, and --no-model disables the optional local-model paragraph.

Execution

Roles and runners

A role is the interface; a runner is the installed program that executes it. Two agents of one role may use different runners.

mctl role runners
mctl role coordinator --use NAME
mctl role runs-on AGENT_ID --use NAME
mctl role at-once NUMBER

coordinator --use changes the runner for coordinators started from then on. runs-on moves one agent to a runner. at-once controls how many specialist agents on each task run simultaneously; extra agents remain hired and wait their turn.

Mission Control ships runner definitions for Claude Code and Codex CLI. Advanced users can add or override runners in ~/.config/mission-control/runners.json without modifying the product.

Reuse existing skills and agents

Mission Control is not a replacement marketplace. Its importer accepts a role definition you already have—such as an Agent Skill, Claude agent or skill, exported GPT, or plain Markdown—and translates it into the local role-package contract.

mctl role import ROLE_SOURCE_PATH
mctl role import ROLE_SOURCE_PATH --add

The first command is a review: it prints what was understood, what the role would become, and whether its matching rules can actually select it. Nothing is written without --add. The source path is read-only; the approved translation is copied into your company’s role-library/.

Local by design

Files, privacy, and boundaries

  • The UI server binds only to 127.0.0.1.
  • Mission Control has no hosted account, telemetry service, or model API key of its own. This public documentation page counts visits with privacy-first Cloudflare Web Analytics; the downloadable application does not contain that beacon.
  • Your coding-agent CLI still communicates with its own vendor under that tool’s settings and privacy policy.
  • The company folder contains readable roles, task files, status, messages, and artifacts.
  • Local application state lives under ~/.config/mission-control by default. Set MISSION_CONTROL_HOME to override it.
  • Mission Control checks only whether a runner’s sign-in marker exists. Credential values never reach the page, logs, or status files.
Project-folder access is real access.

Agents read and modify the project folder through the coding-agent CLI you selected. Its approval and sandbox settings determine what the agent may do.

Sessions spend

Control cost and autonomy

Hiring an agent writes a durable record. Starting its session is the step that can spend money. Mission Control keeps those concepts separate.

  • Every task gets its own coordinator when dispatched.
  • The default per-task pace is three specialist agents running together; the coordinator is not counted.
  • Agents beyond the pace wait their turn instead of being refused.
  • Queued agents only advance while the app’s courier is running; the UI explains when closing the app prevents the next turn.
  • Finishing a task stops all its sessions. Reopening does not restart them.
  • Unattended permission modes are explicit and runner-specific. Enable them only after reading what the chosen runner permits.

Common problems

Troubleshooting

mctl: command not found

Add ~/.local/bin to your PATH. The installer prints the exact line for your shell.

export PATH="$HOME/.local/bin:$PATH"

Python is too old

Mission Control requires Python 3.11 because it reads TOML runner configuration. On macOS, brew install python supplies a current version. You can also run:

MISSION_CONTROL_PYTHON=/path/to/python3 ./install.sh

No agent session starts

Install tmux, confirm Claude Code or Codex CLI is on PATH, and sign in using that runner’s own command. Then check:

mctl status
mctl role runners

The wrong company opens

The remembered company does not change with your current directory. Name another one deliberately with --company PATH.

An agent is quiet or waiting

Read the exact cause and its transcript before restarting it:

mctl agent logs AGENT_ID
mctl agent attach AGENT_ID

Housekeeping

Move or uninstall

Move the unpacked folder

The installed commands intentionally point to that folder. After moving it, run ./install.sh again from the new location.

Remove Mission Control

rm ~/.local/bin/mctl
rm ~/.local/bin/mission-control

Then remove the unpacked product folder. Your company folder belongs to you and is left untouched.
