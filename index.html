One · Local only

It all happens inside your Mac.

RandComp Studio is a desktop app, not a service. There is no account to make and no RandComp server between you and your agents: the app, your projects, every agent’s terminal and every file it writes stay on your Mac. It drives the AI command-line tools you already have — Claude Code, Codex, Kimi Code or Ollama — just as you would from a terminal.

What does leave your Mac — all of it
  • Your prompts and code → the AI tool you picked. Claude Code talks to Anthropic, Codex to OpenAI, Kimi to Moonshot AI — on your own account, exactly as when you run them yourself. With a model on your Mac (Ollama), nothing leaves.
  • Anonymous usage counts → RandComp. Four events: app opened (at most once a day), project created, MCP client connected, message sent. Each is only the event’s name, a UTC time and a random install ID — no content, no project names, no file paths. It is on by default; Settings → Usage statistics turns it off and deletes anything not yet sent.

Nothing else. RandComp account: none · RandComp copy of your work: none · Your prompts and files sent to RandComp: none. The app’s own server listens on 127.0.0.1 only.

See it for yourself. Disconnect the internet in the demo above — roles on a cloud AI tool pause (their provider needs the internet), the role on a model on your machine keeps going. RandComp itself never needed it.

Internet connected

Honest limit: “local” means RandComp adds no cloud of its own — it does not make Claude Code, Codex or Kimi work offline. A model on your machine keeps going without the internet, but small local models suit small, bounded work.

Two · The right AI for each job

Not one AI grading its own homework.

The checker never saw the builder's reasoning, and may run on a different AI entirely. Mix freely — a strong model for planning, a cheaper one for routine work, a private one for sensitive files.

Pick per role

Planning on Claude Code, building on Codex, a quick check on Kimi, drafts on a model on your machine. Change it any time, even mid-project.

Independent checking

The checker works from the result, not from the builder's story, so blind spots are not shared. It is a second look, not a promise that everything is correct.

Use one when one is enough

More agents cost more tokens. Small jobs stay a single session; teams are for work that earns it.

For developers

Reach your team from a terminal or your AI assistant.

The desktop app is the easy way in. The same local team is also scriptable: SSH back into your Mac from anywhere and use the randcomp command, or point any MCP-capable AI tool at the same local process and ask it what needs you. It is one project and one set of files — never a second copy.

# over SSH, from another machine
randcomp project list
randcomp project ask PROJECT_ID "Add a gift-card page"

# MCP clients (Claude Code, Kimi, …) run:
randcomp mcp

Install the bundled randcomp command from the app menu. The CLI and the MCP server talk only to the RandComp process on your Mac — no extra cloud in between.

What you need first

  • A Mac with Apple silicon (M1 or newer) on macOS 11 or later.

How it started

About RandComp

It started while I was traveling. I wanted agents working on my Mac mini back home — but one long AI session goes out of shape fast: it drifts, loses the plot, and no one is there to catch it. So instead of one agent doing everything, I built a company: a coordinator plans the work, each role owns a piece, and I can attach to any of them from wherever I am. Then I kept using it myself — several small apps later, it had earned its place as my default way of working. That's when I decided it was time to share it. As for the name — I couldn't think of one, so Random Company it is. RandComp is just the shortcut.
