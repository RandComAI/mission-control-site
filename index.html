A local control center for parallel AI sessions

Coordinate parallel AI sessions without managing them by hand.

One long AI session mixes research, decisions, implementation, and review into the same growing context. Opening several smaller sessions keeps each job focused—but leaves you assigning work, copying context, tracking progress, and finding results yourself.

RandComp Studio gives that work one task, runs named roles in separate command-line AI sessions, connects their handoffs, and shows every session, dependency, message, and result on one local board. You can inspect or take over any session at any time.

One local system, two ways to operate it. Use the desktop board directly or connect it to an MCP-capable AI session. This build requires Apple silicon, macOS 11 or newer, and a supported command-line AI agent installed and signed in.

Direct the same crew from your AI session.

Stay in an MCP-capable AI session and ask it to use RandComp Studio for work that should run separately. RandComp Studio creates durable tasks and role sessions underneath, while the board keeps their progress, terminals, handoffs, and files visible whenever you want to inspect them.

Required: an AI client that can run a local MCP server, plus randcomp on PATH. From the downloaded app, choose RandComp Studio → Install the randcomp command in PATH first.

claude mcp add -s user randcomp-studio -- randcomp mcp

That command is the Claude Code setup example. Other MCP clients register the same local randcomp mcp process in their own settings.

Registering also adds four slash commands for the things you start a message with. Claude Code 2.1.233 shows them as /mcp__randcomp-studio__catch-me-up and three more; other clients spell the same four names their own way.

Desktop app

Start from the board

  1. Choose the project folder and enter the goal in Say what you want done.
  2. Allow Product Manager, Developer, and QA. The coordinator divides the task among those roles.
  3. Each role works in its own focused local AI session. Their instructions and task context stay separate; their messages and dependencies stay connected.
  4. Watch the graph, open a live session, redirect an agent, and inspect the files and final result from the same task view.

Keep your tools. Add the team layer.

RandComp Studio runs the command-line AI agents you already use, giving separate sessions durable roles, clear task boundaries, visible coordination, and results you can inspect. It is the coordination layer—not another AI agent or chat app.

It does not replace ChatGPT skills, Claude skills and plugins, or other role ecosystems either. Import a definition you already use, review the translation, and add it to your local role library only when you approve.

  • Bring your preferred runnerChoose which command-line AI agent each role uses, with the account and approval settings you already have. This preview includes Claude Code and Codex runners; additional runners are the next compatibility step.
  • Bring your existing expertiseTurn an Agent Skill, Claude agent or skill, exported GPT, or plain Markdown definition into a reusable role for your crew.

Split the context. Keep the team connected.

An all-purpose session has to keep re-reading a growing history, even when the next job needs only a small part of it. Give research, implementation, and review their own role sessions with job-specific context instead. RandComp Studio keeps the brief, dependencies, messages, and handoffs connected while you stay in charge.

Every session works in a folder you choose through its selected runner. RandComp Studio stores no model credentials of its own.

Define roles once. Assemble the right team for each task.

The role library is your reusable crew: definitions of the work each role is good at, the instructions it follows, and what it has done before. Create roles locally or translate definitions you already use with ChatGPT, Claude, and other agent tools. A role becomes a running agent only when a task hires it.

For each task, choose the roles yourself or let the coordinator select from the set you allow. You decide who may run before another session can start or spend money.

How the crew works

Focused sessions. Visible handoffs. You in control.

  1. Start a task with one outcome and choose which roles it may use.
  2. RandComp Studio gives each hired role a separate local session and a clear part of the work.
  3. The crew can pass work and messages between roles while you follow the live state from the board or your AI session.
  4. Step into any terminal when needed, then inspect the recorded outcome and every file the task produced.

Each agent has a terminal.

These are not hidden background workers. Every agent is a real session you can watch, read, redirect, or take over completely. 

randcomp agent list TASK_ID
randcomp agent logs AGENT_ID
randcomp agent send AGENT_ID "..."
randcomp agent attach AGENT_ID

Copy TASK_ID and AGENT_ID from the commands' own output. A session outlives the command that started it, so closing the window does not end the work.

One command surface for the whole team.

randcomp and randcomp-studio are the same program; randcomp is shorter to type. Every command names the thing first and the action after: the plural noun on its own is a listing, a word after it names one, and a word after that says what to do with it.

Open work, read what came back, talk to any agent, bring in a role somebody else wrote, or inspect the whole team—from one command surface with one shape.

randcomp task create "Ship the landing page"
randcomp task list
randcomp task results TASK_ID
randcomp agent list TASK_ID

randcomp agent logs AGENT_ID
randcomp role import ./some-claude-skill --add
randcomp status

What you need

macOS 11 or newer, Apple silicon
The download is an arm64 build, so it runs on M1 and later. Intel Macs are not supported yet.
Windows and Linux
Coming soon. Their download buttons are disabled until supported builds exist.
Python — already inside
The application carries its own Python 3.13, because the one macOS ships in /usr/bin is 3.9 and too old. You do not need to install anything, and it does not touch whatever Python you do have.
tmux — already inside
Each role runs in a tmux session that outlives the command that started it. A copy is in the application, so there is nothing to brew.
A command-line AI agent you already have
RandComp Studio drives the runner you have and already sign in to; it does not include one. This preview includes definitions for Claude Code (claude) and Codex CLI (codex), with additional command-line agents planned next.

What it can access

  • A company folder, created on the first run, wherever you pick in the folder chooser. Roles, tasks and what each agent produced live there, as ordinary files.
  • The folders you point work at. Agents read and change them through your command-line AI agent, under that CLI's own approval settings — the same ones that apply when you run it yourself.
  • A local web server for the dashboard, bound to 127.0.0.1 on a port the operating system had free, which stops when you close the window.
  • No product account, telemetry, or hosted service, and nothing in the downloaded app to sign up for. This public website counts visits with privacy-first Cloudflare Web Analytics; the application does not contain that beacon. Your command-line AI agent still communicates with its own vendor under its own settings and privacy policy.

Install and start

Open the desktop app when you want the board in its own window. Connect the local MCP server when you want an AI session to operate the same tasks and crew without leaving the tool you already use.

Desktop app

Three things, and none of them is typing.

  1. Download RandCompStudio-0.1.0-e5fe0ab9.dmg.
  2. Open it. A window appears with the application and a shortcut to your Applications folder.
  3. Drag RandComp Studio onto Applications, then open it from there.

The first run asks once, in an ordinary folder chooser, where your company should live — then never asks again. To remove it later: drag the application to the Trash. Your company folder is yours and is left alone.

The randcomp command is a menu item, not an installer. Everything the window does has a terminal equivalent, and RandComp Studio → Install the randcomp command in PATH is where you get one: it writes randcomp and randcomp-studio into ~/.local/bin and tells you if that folder is not on your PATH yet. Nothing is written there until you ask for it.

Inside your AI session over MCP

Your AI client must support a local MCP server, and randcomp must be on PATH. If you installed the disk image, open RandComp Studio and choose RandComp Studio → Install the randcomp command in PATH. For Claude Code, register it with:

claude mcp add -s user randcomp-studio -- randcomp mcp

The MCP server is the local randcomp mcp process speaking over stdin and stdout. It opens and manages the same tasks, roles, agents, sessions, messages, and result files as the app. It is not hosted and needs no RandComp Studio API key.

Or from the command line

The same tool, without the application bundle — this is the one to take if you would rather read every line before you run it. It needs Python 3.11 or newer and tmux on your own machine, which the disk image would have brought with it. 

tar -xzf randcomp-studio.tar.gz
cd randcomp-studio
./install.sh

install.sh puts randcomp in ~/.local/bin, which macOS does not have on your PATH by default. If it says so, add the line it prints to your ~/.zshrc, open a new terminal, and then run randcomp — it only prints that when it is needed.

randcomp-studio.tar.gz — open install.sh in a text editor first; it is short and it is the whole install. It creates only ~/.local/bin/randcomp and ~/.local/bin/randcomp-studio, two shell scripts naming the folder you unpacked and a Python it found. It installs no packages, copies nothing anywhere else, and starts no background service.

RandComp Studio runs on your machine, against folders you choose, using a command-line AI agent you are already signed in to. Read the documentation.
