Keep your tools. Add the company layer.

Mission Control does not replace the agent you trust. It gives your existing coding-agent CLI durable roles, task boundaries, coordination, live visibility, and a result you can inspect.

It also does not replace ChatGPT skills, Claude skills and plugins, or other role ecosystems. Import a definition from a file or folder you already use; Mission Control reads the source, shows the translation first, and adds it to your local role library only when you approve.

A team assembled around the work.

Describe an outcome. A coordinator selects matching roles from the shipped library—Developer, QA, Designer, Market Analyst and others—then briefs each one in a session of its own.

It works in folders you choose, through a coding-agent CLI you already use. Mission Control stores no model credentials of its own.

Build the company once. Staff each task deliberately.

The role library is your reusable company: definitions of who can be hired, what each role is for, and its track record. Create roles locally or translate definitions you already use with ChatGPT, Claude, and other agent tools. Roles are not running agents until a task hires them.

For each task, let the coordinator choose from the library or narrow the available set yourself. The control stays with you before any session starts or spends money.

The operating model

One request in. Coordinated work out.

  1. You describe the task in one sentence.
  2. Mission Control opens a task, takes on the roles it needs, and gives each one a tmux session.
  3. Each agent works through its part in the coding CLI you already use.
  4. You read what came out — the recorded outcome, and every file in the task's own folder — on the page or with mctl task results TASK_ID.

Each agent has a terminal.

Every agent is a real session you can walk up to. Watch one work, read everything it has said, write a line into it, or take it over completely. 

mctl agent list [TASK_ID]
mctl agent logs AGENT_ID
mctl agent send AGENT_ID "..."
mctl agent attach AGENT_ID

Copy TASK_ID and AGENT_ID from the commands' own output. A session outlives the command that started it, so closing the window does not end the work.

One grammar for the whole company.

mctl is the same program as mission-control, with less to type. Commands follow the thing first, then the action.

Create and inspect tasks, work directly with agents, manage the role library, or read the whole company from one consistent command surface.

mctl task create "Ship the landing page"
mctl task list
mctl task results TASK_ID

mctl role library
mctl agent list [TASK_ID]
mctl status
mctl inbox

What you need

macOS
Available now.
Windows and Linux
Coming soon. Their download buttons are disabled until supported builds exist.
Python 3.11 or newer
No Python packages are installed and there is no virtual environment. The Python macOS ships in /usr/bin is 3.9, which is too old; brew install python gives you a newer one. The installer says so and stops rather than half-working.
tmux
Each role runs in a tmux session. Without tmux everything you read still works, and launching a role refuses.
A coding-agent CLI you already have
Claude Code (claude) and Codex CLI (codex) are supported. Mission Control drives the one you have and already sign in to; it does not include one.

What it can access

  • A company folder, created on the first run, wherever you pick in the folder chooser. Roles, tasks and what each agent produced live there, as ordinary files.
  • The folders you point work at. Agents read and change them through your coding-agent CLI, under that CLI's own approval settings — the same ones that apply when you run it yourself.
  • A local web server for the dashboard, bound to 127.0.0.1 on a port the operating system had free, which stops when you close the window.
  • No product account or product telemetry. Mission Control has no hosted service of its own. This public website counts visits with privacy-first Cloudflare Web Analytics; the downloadable application does not contain that beacon. Your coding-agent CLI sends what it sends to its own vendor, under its own settings and privacy policy; that is unchanged by running it from here.

Private preview

The public download is not open yet. If you want to try the current macOS preview, open an issue and tell me how you want to use it.

Before running it, open install.sh in a text editor — it is short and it is the whole install. It creates only ~/.local/bin/mctl and ~/.local/bin/mission-control, two shell scripts naming the folder you unpacked and a Python it found. It installs no packages, copies nothing anywhere else, and starts no background service.

If your shell then answers mctl: command not found, ~/.local/bin is not on your PATH, and the installer has already printed the one line to add.

mctl opens the dashboard. The first run asks once, in an ordinary folder chooser, where your company should live — then never asks again. To remove it later: delete those two scripts and the unpacked folder.
